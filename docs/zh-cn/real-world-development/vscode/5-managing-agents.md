启用 GitHub Copilot 智能体模式后，它会自主工作，包括探索代码库、提出更改、编辑文件和运行命令。由于这些工作实时发生在你的计算机上，VS Code 中的 Copilot Chat 会持续显示每次工具调用和文件编辑。你可以内联审查每个差异、接受或拒绝单项更改，并通过后续提示引导对话、完善或扩展工作，全程无需离开编辑器。

在本练习中，你将：

- 实时监控无障碍智能体的工作；
- 审查并接受建议的文件编辑；
- 在会话进行期间引导智能体，在高对比度模式旁添加浅色模式开关。

## 场景

你在[练习 4][previous-lesson]中使用的无障碍自定义智能体正在实现高对比度模式。工作进行期间，设计团队提出了额外需求：为觉得默认主题太暗的用户添加浅色模式开关。你无需从头开始新对话，而是引导当前会话扩展工作。

## 监控 Copilot 的进度

Copilot Chat 视图会显示智能体执行的每个步骤，包括探索的文件、运行的命令和建议的编辑。每项文件编辑都会在聊天中内联显示差异和 **Keep** / **Undo** 控件。

1. 返回练习 4 中打开的 Copilot Chat 视图。
2. 智能体工作时，滚动聊天内容，查看每次工具调用。你会看到文件读取、文件编辑，以及它请求运行的终端命令。
3. 智能体建议编辑文件时，聊天中会内联显示差异：
    - 选择 **Keep** 接受更改；
    - 选择 **Undo** 撤销更改，让智能体再次尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看智能体在本次会话中修改的全部文件。

> [!NOTE]
> 如果工具调用请求权限（例如运行终端命令），智能体会暂停并显示 **Allow** 提示。只批准你信任的命令。

5. 等待智能体完成高对比度模式。完成后应会显示一条消息，总结所做的更改。

## 引导智能体添加浅色模式

高对比度模式实现后，你可以在同一对话中继续添加浅色模式开关。由于仍在同一个聊天会话中，智能体会保留先前工作的上下文，包括修改的组件、使用的样式方案和本地存储模式。

1. 在 Copilot Chat 输入框中发送以下后续提示：

    ```plaintext
    做得不错！现在在高对比度开关旁添加浅色模式开关。浅色模式应采用相同方案：通过 local storage 保存，并可从 UI 的同一区域访问。用户应能独立启用高对比度模式和浅色模式。
    ```

2. 智能体会继续处理，探索已有更改，并提出添加浅色模式的方案。
3. 像审查高对比度模式一样，逐项检查新更改。对每项差异使用 **Keep** 或 **Undo**。
4. 如果智能体的处理方式不符合预期，例如试图以你不喜欢的方式重构开关 UI，可以选择聊天输入框旁的 **Stop** 按钮停止任务，然后发送澄清提示。

> [!TIP]
> 引导正在进行的会话比从头开始更快。可以使用后续提示调整方向，例如“简化 CSS，改用 CSS 变量，不要重复选择器”、“不要添加第三个开关；将浅色模式整合到现有设置面板中”，或扩展范围，例如“也为两个开关添加键盘快捷方式”。

## 审查工作集

提交更改前，快速检查智能体修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 查看已更改文件的完整列表。你应该能看到 Astro 组件、样式和相关测试的更新。
3. 打开几个已更改文件，查看差异。确认自定义智能体使用的无障碍模式已经体现在代码中，包括 ARIA 属性、键盘导航、语义化 HTML 和使用本地存储保存设置。
4. 确认满意后，在 Source Control 面板中暂存并提交更改。下一课会发布这些更改。

## 总结和后续步骤

你已使用 Copilot Chat 智能体模式监控并引导正在进行的会话，逐项审查文件编辑、接受或拒绝更改，并通过后续提示扩展工作，同时保留上下文。

在本课中，你：

- 实时监控智能体工作；
- 接受或拒绝单项文件编辑；
- 使用后续提示引导正在进行的会话。

在[下一课][next-lesson]中，你将把无障碍功能作为拉取请求发布，并审查本实验中本地自定义智能体生成的更改。
